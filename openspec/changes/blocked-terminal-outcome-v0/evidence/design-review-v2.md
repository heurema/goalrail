# «Blocked» в Goalrail — конструкция v2 после панели из пяти линз

Пять независимых ревьюеров (простота, машина состояний, злоупотребление,
эволюция контракта, продуктовая заявка), каждый читал реальный код Goalrail.
41 находка; ниже — консенсус (подтверждено ≥3 линзами), одно разногласие
и пересобранная конструкция.

## Мою исходную конструкцию разобрали по трём швам

**1. Поле escalation-path в WorkSpec — лишнее и внутренне противоречивое.**
(простота CRIT, контракт CRIT, gaming, продукт — 4 линзы)
Путь «вне writable paths» провайдерский sandbox просто не даст записать —
канал был бы мёртв, агенты вернулись бы к угадыванию. А любое новое поле
форкает `goalrail.work-spec/v0`: `DecodeWorkSpec` использует
`DisallowUnknownFields`, старые бинарники отвергнут новые спеки, digest-ы
замороженных WorkSpec под угрозой.
→ **Вместо поля — зарезервированный константный путь** (`.goalrail/blocked.md`).
WorkSpec не меняется вообще. Ключевая посылка брифа «это contract change
WorkSpec» оказалась ложной — объём меняется только у квитанции.

**2. «Исключить артефакт из дельты» — моя ошибка, единогласно.**
(gaming CRIT, контракт CRIT, машина состояний, простота)
Исключённый из дельты файл = единственный неаудируемый канал записи во всём
контракте: подмена невидима, «rm blocked.md && gr finish» даёт `passed`,
квитанция переживает доказательство, которое сертифицирует.
→ **Артефакт остаётся в observation/changed_paths** (но не в scope_violations),
и его байты **эагерно копируются в append-only run store** в момент
provider observation — симметрично существующему `failureReceipt`
(service.go:296-305). Квитанция несёт digest + ссылку на удержанную копию.
Дыра «удалил файл перед finish» закрывается конструктивно.

**3. Схема вопроса переобучена под кату про конфликт документов.**
(простота CRIT, машина состояний, gaming)
Блок-класс «зависимость не существует» или «окружение сломано» не имеет ни
двух источников, ни разделяющего примера. Валидировать семантику в Goalrail —
нарушить его же границу («не выполняет проверки»).
→ **Для Goalrail артефакт — непрозрачные байты** с гигиеной по образцу
`validateRetainedText`: обычный файл (не symlink), ≤64 KiB, UTF-8, не пусто,
secret-scan. Семантическая схема (`goalrail.escalation/v0`: sources, example,
interpretations, question — с опциональными полями под разные блок-классы)
живёт как отдельный провайдер-нейтральный формат, который валидируют
даунстрим-инструменты (оракул каты уже это делает). Одна семья схем с baseline,
не две.

## Консенсусные правила состояний (были не определены)

| ситуация | правило | кто настоял |
|---|---|---|
| артефакт существует уже на baseline | `gr prepare` отказывает: `ESCALATION_ARTIFACT_PRESENT` | машина состояний CRIT: иначе чужой/старый вопрос привязывается к новому прогону |
| артефакт + правки в scoped paths | **не** blocked → `failed` + `BLOCKED_WITH_EDITS`, артефакт удержан | машина состояний CRIT, контракт: иначе агент хеджирует — и патч, и вопрос, что прилипнет |
| unlinked / denied / launch_failed | побеждают blocked; digest вопроса — в reasons, но статус не blocked | неатрибутируемая сессия не должна чеканить авторитетный вопрос |
| TOCTOU между чтением артефакта и записью receipt | один Observe-снапшот решает и дельту, и артефакт | машина состояний |
| finish с явными `--result` при артефакте | результаты записываются **дословно**, статус никогда не `passed` | см. разногласие ниже |
| grammar `--result` | без изменений; blocked — не четвёртое состояние проверки, а вычисляемый исход прогона | контракт |

## Единственное разногласие панели — и моё решение

**«Проверки остаются unavailable» при blocked.** Gaming-линза показала: это
превращает blocked в **канал уничтожения улик** — агент с красными проверками
конвертирует `failed` → `blocked`, и провальные результаты испаряются из
квитанции. Машина состояний предлагала отказывать в finish с явными
результатами; простота — записывать дословно.

Решение: **записывать дословно, статус никогда не passed**. Отказ создаёт
тупик; дословная запись сохраняет улики в обе стороны и ничего не фабрикует.
Blocked ортогонален результатам проверок, а не заменяет их.

## Заявка честно ужимается

«Тот же конфликт никогда молча не повторится» — **не доставляется** этой
конструкцией (продукт CRIT, простота, контракт): ничто не мешает новому
WorkSpec сослаться на старую, до-ответную версию интента. Строить реестр
отвеченных вопросов = новый скоуп, запрещённый контрактом workspace.

Новая формулировка: **«вопрос и решение — проверяемые версионированные
артефакты, машинно связанные в цепочку; прогон не может закрыться как
выполненный, пока решение не принято»**.

Чтобы цепочка была машинно-проходимой (сейчас — нет!):
- квитанция получает `intent{id, version, digest}` из замороженного WorkSpec
  (сегодня квитанция интент вообще не несёт);
- отвечающая версия интента получает опциональное поле
  `resolves = {run_id, escalation_digest}` + `disposition`
  (`answered | spurious | withdrawn`) — «spurious» делает ленивый blocked
  видимым и накапливаемым, отвечая и на DoS-находку (цена вопроса для
  владельца), и на обратный риск (культура наказания за вопросы).

## Открытое решение для владельца: статус

**Вариант A (рекомендую):** первоклассный статус `blocked` + явное
версионирование квитанции `goalrail.terminal-receipt/v1` (сейчас у квитанции
вообще нет поля схемы — контрактная линза считает «v0-additive» фикцией, любой
новый статус и так ломает читателей через whitelist в
validateTerminalReceipt:618-622). Раз ломаем — ломаем честно, один раз, с
версией.

**Вариант B (минимальный):** без нового статуса — `verification_incomplete` +
reason `ESCALATION_PENDING` + два omitempty-поля. Ноль поломок сегодня, но
blocked-триаж владельца становится вторым классом, и повышение до
первоклассного статуса потом — вторая миграция.

## Итоговый объём v2

- `goalrail.work-spec/v0` — **не меняется** (был главный страх — снят).
- Квитанция — `terminal-receipt/v1`: `schema`, `escalation{path,digest,ref}`,
  `intent{id,version,digest}`, статус `blocked` (при варианте A).
- `localrun`: гейт в prepare, эагерный захват в Start, правила precedence,
  finish-семантика. Примерно та же поверхность, что у admission boundary из #12.
- `goalrail.escalation/v0` — новая маленькая спека формата вопроса
  (валидируется вне Goalrail).
- Интент-схема (openspec-сторона): `resolves` + `disposition`.
- Фикстурный регресс-тест: digest замороженного v0-WorkSpec байт-в-байт.

Отдельная фаза (не сейчас): детерминированное citation-grounding — каждая
цитата источника в вопросе обязана байт-совпадать с файлом на замороженной
BaseRevision (read-only git-lookup, «Goalrail не выполняет проверки» не
нарушается). Убивает сфабрикованные вопросы, но это вторая итерация.
